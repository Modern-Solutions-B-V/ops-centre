## Boundaries

- Native host Ollama remains the inference path.
- QR1 does not bind Ollama to `0.0.0.0`; containers reach it through `ms-qr1-host:<MS_QR1_HOST_GATEWAY>`, which points at the actual non-internal ODS Docker gateway where the host-side HTTP bridge listens. The systemd unit executes the installed root-owned bridge copy under `/usr/local/libexec/ms-qr1/`, not mutable checkout code. The bridge forwards only to `127.0.0.1:11434`, rewrites upstream `Host` to `localhost:11434`, preserves streaming Ollama responses with incremental reads, streams request bodies upstream in bounded slices, caps request bodies at 256 MiB by default, closes truncated fixed-length upstream responses promptly, and uses a 300 second upstream timeout by default.
- QR1 `prestart-init` must run before any `docker compose up`, including `up --no-start`, because Compose creates containers and evaluates bind mounts before starting services.
- Privileged filesystem repair follows `docs/ms/decisions/QR1-QUIESCENT-PRIVILEGED-PROVISIONING.md`: rendered containers that can write the affected persistent data paths must be stopped before repair; runtime checks are read-only. QR1 derives writer services from rendered writable bind mounts before running Langfuse or QR1 data repair.
- `data/persona/SOUL.md` is generated by `scripts/build-installation-context.py` before Hermes can evaluate its file bind mount, then refreshed after stack startup through `scripts/ms-qr1-prestart-provision.sh poststart-refresh`; both writes use a same-directory temporary file and atomic replacement. Post-start refresh recreates `hermes` so Docker re-establishes the file bind mount against the refreshed inode, copies `/opt/hermes/docker/SOUL.md` to `/opt/data/SOUL.md` inside the recreated container, restarts Hermes, waits on Docker health, and recreates `hermes-proxy`. QR1 must not publish Hermes host port `9119`.
- `data/n8n` ownership is corrected only for that directory tree, using the effective rendered n8n UID/GID from Compose; directory and file modes are normalized separately before first start, runtime checks allow n8n-created read bits while still rejecting missing owner-write, missing owner-search on directories, group/world-write, symlinks, wrong owners, and unexpected file types, and no broad `data/` chown or world-writable permission is part of QR1.
- Langfuse PostgreSQL/ClickHouse ownership repair is also behind the quiescent-state ADR for QR1 because the runbook stops and verifies derived QR1 writers before invoking `extensions/services/langfuse/hooks/post_install.sh`. Generic dashboard-driven Langfuse setup and Docker-rootless repair hardening are documented as deferred lifecycle findings in `docs/ms/backlog/GENERIC-ODS-LIFECYCLE-HARDENING.md`; this PR does not redesign those upstream ODS flows.
- UFW rules are scoped from non-internal Docker CIDR(s) to their matching Docker gateway on TCP `11434` and `7710`; the internal Langfuse network is excluded.
- The host-agent systemd service is a required QR1 host prerequisite because the approved trust matrix includes dashboard-api host-agent access on `7710`.
- No AMD tuning, UMA/GTT/IOMMU, Lemonade, email, Jira, client-system credentials, production secrets, ODS Tailscale extension, ods-proxy, Brave Search, OpenClaw, ODS OpenCode extension, remote-provider egress service, or remote-provider SSH tunnel are enabled.
- `model-router` remains present in the rendered QR1 stack as an inert/internal core service: it publishes no port and its configured endpoint points only at excluded `llama-server:8080`, so it is not a QR1 egress path.
- Hermes dashboard TUI is forced off with `HERMES_DASHBOARD_TUI=0`.
- Qdrant and SearXNG require non-empty generated secrets.
- Host-agent nmcli routes have no supported disable switch in upstream config; QR1 documents and tests unauthenticated denial instead of editing core host-agent code.
- LiteLLM scoped virtual consumer keys are deferred to QR2. QR1 shares the LiteLLM master key with Open WebUI and Hermes because there is no clean CONFIGURE-only virtual-key provisioning path in this ODS profile without adding deployment complexity or touching core code.
- Clean Ubuntu 24.04 deploy hosts must have `python3-yaml`, `jq`, and `curl` before QR1 validation; `jq` is required by `scripts/validate-env.sh` and `curl` is required for the post-start Hermes health gate.
